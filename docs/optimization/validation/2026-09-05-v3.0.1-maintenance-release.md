# v3.0.1 public maintenance release

The operator approved preparing, validating and publishing a fixes-only
maintenance release. GitHub publication completed on 2026-09-05 at 21:09:10 UTC:
[v3.0.1 — Fee and Admission Correctness Maintenance](https://github.com/lightning-goats/cl_revenue_ops/releases/tag/v3.0.1).
It is a published, non-prerelease release, not a draft.

## Exact source and scope

- Base: `v3.0.0`, commit `631bc6bbcd02a133f08d2d2eea9daaa433058ada`.
- Release: `bf7c99edf71b153d8a80e789d69acc7f0e3c9e46`.
- Dedicated branch: `release/3.0.1`; annotated tag: `v3.0.1`.
- Runtime changes: `modules/admission_policy.py` and
  `modules/fee_controller.py`, plus the `PLUGIN_VERSION` change to `3.0.1` in
  `cl-revenue-ops.py`.
- Backports: liquidity-safe HTLC floor from `5d3242b`; fresh fee-decision
  channel evidence from `da61cb3`; independent admission/fee thresholds from
  `aa79eba`, each with its applicable regression coverage.
- Excluded: yield-aware mode, its two-sided inventory-wake correction, the
  uncommitted v30 pricing candidate, rejected v33 reserve, and unrelated
  operator/xrebalance changes. The wake correction needs a feature absent in
  v3.0.0; importing that feature would violate the fixes-only release scope.

Configuration, requirements, schema, database, rebalancer and profitability
implementation are unchanged from v3.0.0. Neither competitors nor tournament
inputs/scoring were changed. Historical v3.0.0 development tools in the
maintenance ancestry were not reintroduced on development `main`.

## Verification

A separate clean local clone kept the main worktree and its uncommitted work
out of the release. All selected patches were applied with `apply_patch` and
reviewed relative to v3.0.0. The runtime source contains no `yield_aware` mode
or `should_wake_yield_inventory_cycle` implementation.

Focused tests passed 381 checks across admission policy, fee execution and
pipeline composition, economic regressions, HTLC golden fixtures, architecture,
operator surfaces and the read-only RPC inventory. The exact committed release
then passed the full suite:

```text
python -m pytest -q -ra
4154 passed, 5 skipped, 2 xfailed in 171.38s (0:02:51)
```

The project `.venv` interpreter was used; system Python lacks pytest. Four
live-router checks intentionally remained disabled (`CLN_INTEGRATION` unset),
one optional integration lacked `pyln.testing`, and two pre-existing
staged-removal tests were expected failures. No test or competitive gate was
relaxed. The retained full log is `results/maintenance-v3.0.1/pytest-full.log`.
Python compilation and `git diff --check` passed; the exact-release checkout
was clean before and after tests.

## Production and remaining limits

Read-only production verification still found clean `aa79eba`, healthy loops,
46 managed channels and zero active rebalance jobs. That newer development
revision already contains the applicable fixes. Publishing a maintenance tag
does not justify downgrading it; no production restart, configuration mutation,
manual fee/rebalance cycle, or fund transfer was performed for this release.
There is no Sling dependency, external coordinator or Archon DID creation.

The release notes explicitly distinguish production's revision from this tag.
They do not claim measured earnings gains, yield-aware readiness or competitor
superiority. Native propagation and sender-learned liquidity constraints remain
unresolved competitive risks. Development `main` now points installation and
maintenance-upgrade instructions to the stable tag without claiming to be the
same runtime source.
